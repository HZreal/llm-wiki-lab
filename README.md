# LLM Wiki：我的第二大脑

这是一个由 LLM Agent 协助维护的个人知识库，基于 [Karpathy 的 LLM Wiki idea](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)。你负责选择资料、提出问题，Agent 负责总结、提炼概念、关联旧知识和持续修订。

资料和探索成果保存为 Markdown 文件，可以在 Obsidian 中阅读、查看链接关系，也可以直接交给 Agent 检索。

## 工作机制

- **摄入（ingest）**：阅读原始资料，创建来源总结，更新相关知识页、索引和日志。
- **查询（query）**：优先基于 wiki 回答并引用来源，必要时回看原文；有价值的回答可以继续沉淀。
- **检查（lint）**：检查断链、遗漏、冲突、过时内容及待处理资料。

知识会随新资料持续积累和修订。所有操作由你在会话中发出指令触发，没有后台自动监视。

## 目录

| 路径 | 用途 |
|---|---|
| `raw/` 根目录 | 待摄入的源文件 |
| `raw/assets/` | 图片等附件，不单独摄入 |
| `raw/ingested/` | 摄入成功后的原文归档 |
| `wiki/` | 来源总结、概念、对比和综合知识 |
| `templates/` | 页面模板 |
| [AGENTS.md](AGENTS.md) | Agent 的完整工作规则 |

导航入口：[首页](wiki/overview.md) · [知识索引](wiki/index.md) · [演化日志](wiki/log.md)

## 怎么使用

1. 在支持读取本地文件的 LLM Agent 中打开本仓库，让它先读取 `AGENTS.md`。
2. 将文章、笔记等源文件放到 `raw/` 根目录，附件放到 `raw/assets/`。建议使用 Markdown；其他格式能否处理取决于 Agent 的读取能力。
3. 发出“摄入新增资料”指令。Agent 只处理根目录源文件，成功后移到 `raw/ingested/`；失败或部分完成的文件留在原位。
4. 浏览 wiki 或继续提问，需要保留的结论让 Agent 保存为知识页。

不要手动把未处理文件放进 `ingested/`。更新资料时把新版本放回根目录，保留旧归档；Agent 会关联版本并修订知识。归档表示摄入完成，不代表来源一定正确。

## 常用提示词

以下都是自然语言指令，可以直接发送给 Agent，并按需替换文件名或主题。

| 场景 | 提示词 |
|---|---|
| 开始会话 | 请先读取 AGENTS.md、wiki 首页、索引和最近日志，按仓库规则工作。 |
| 摄入新增资料 | 请摄入 raw 根目录下所有新增源文件，成功后归档，最后报告新增、更新、移动和未完成的文件。 |
| 摄入指定文件 | 请摄入 raw/文章.md，提炼关键观点，更新相关页面并补交叉链接，成功后归档。 |
| 查询知识 | 请基于 wiki 回答：LLM Wiki 和 RAG 有什么差别？必要时回看原始资料，并给出引用。 |
| 保存回答 | 请把刚才的回答整理到 wiki，优先更新已有同主题页面，补来源、链接、索引和日志。 |
| 对比资料 | 请比较 wiki 中关于主题 A 和主题 B 的内容，说明共同点、差异及证据缺口。 |
| 查看待处理项 | 请列出 raw 根目录的待摄入文件，以及已有的部分处理记录。 |
| 健康检查 | 请检查知识库的链接、索引、归档一致性、内容冲突和过时结论，修复明确问题并生成报告。 |
| 复核归档 | 请复核 raw/ingested/文章.md 对应的知识页，检查是否遗漏或误解，不改原文。 |

需要调整维护方式时，直接说明需求，让 Agent 同步更新 `AGENTS.md` 和相关说明页。
