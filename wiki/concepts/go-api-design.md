# Go API 设计

## 定义

API 设计要明确调用者可依赖的能力与数据格式，保留内部实现的演化空间。

## 接口与实现

原文 128–302 行建议通常传接口值，结合值/指针方法集判断实现，必要时通过 `var _ Interface = (*Type)(nil)` 等编译期检查表达约定。这里是惯用模式，具体类型名需替换；本次没有编译测试。
中文补充中的“接口本身就是一个指针”过于简化，不沿用为概念定义；接口的完整表示及方法集语义后续专项核验。

## 组合与稳定契约

- 通过命名字段和显式委托隐藏实现；嵌入前确认被提升的方法和字段都应成为外部 API。来源 604–646、1040–1073 行。
- 序列化字段使用显式 tag，避免内部字段重命名意外改变外部格式。来源 749–758 行。
- 可变依赖通过构造参数或对象字段传入，减少全局变量及 init 副作用，改善测试替换。来源 595–603、660–681 行。
- 多个可选且需要扩展的构造参数可采用功能选项模式，允许调用者只指定偏离默认值的选项。来源 1313–1379 行。

功能选项是指南建议的模式，不要求所有小型构造函数使用；接口式与闭包式的选择也属于设计权衡。
